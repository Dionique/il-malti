# AGENTS.md — как работать в этом репозитории

Приложение для изучения мальтийского: слова, фразы, формы, диалоги.
Полностью статическое — HTML, CSS, JS и файлы данных. Ни сборки, ни бэкенда,
ни зависимостей.

**Рабочий цикл — от требований:**

```
требование в specs/  →  код  →  проверка с тем же REQ-идентификатором
                     →  bin/deploy (тесты, сборка, публикация, проверка сайта)
```

Подробности процесса — в [specs/README.md](specs/README.md).

## Команды

```bash
bin/deploy                     # проверить всё, ничего не публиковать
bin/deploy -m "сообщение"      # + коммит, push, ожидание Pages, тесты сайта

python3 tools/check_specs.py   # требования <-> проверки
python3 tests/smoke.py         # 208 проверок в реальном браузере
python3 tests/smoke.py --root dist                 # против собранного каталога
python3 tests/smoke.py --url https://dionique.github.io/il-malti/   # против прода

python3 tools/make_transcription.py   # транскрипции (IPA + кириллица)
python3 tools/make_links.py           # связи фраз со словарём
python3 tools/make_forms.py --check   # правило артикля на всём словаре
python3 tools/make_forms.py           # формы: согласование, мн. ч., предлоги
python3 tools/make_blanks.py          # упражнения на пропуски
python3 tools/check_dialogues.py      # переводы и лексика диалогов

bin/build                      # собрать dist/
bin/build --out docs           # собрать в docs/ (это и публикуется)
bin/maltese status|restart|logs        # локальный сервер на maltese.localhost:8080
```

## Структура

```
index.html  styles.css  app.js      приложение (app.js — вся логика)
data/                               данные: слова, фразы, диалоги, упражнения
  words.js        словарные статьи
  sentences.js    фразы
  dialogues.js    диалоги
  pairs.js  forms.js  blanks.js     упражнения (генерируются)
  links.js  ipa.js                  связи и транскрипции (генерируются)
specs/                              требования
tests/smoke.py                      единственный набор проверок
tools/                              генераторы данных и проверки
bin/                                build, deploy, управление сервером
docs/                               собранный сайт (публикуется)
server.js                           локальный сервер для разработки
```

## Правила, которые нельзя нарушать

1. **Требование без проверки — не требование.** Новое поведение = запись в
   `specs/` + проверка, в подписи которой есть идентификатор:
   `check("REQ-SENT-09 после ответа есть кнопка «Дальше»", ...)`.
   `tools/check_specs.py` падает, если трассировка нарушена.

2. **Данные генерируются, а не правятся руками.** Изменение `words.js`
   требует прогона генераторов (см. команды). Порядок фиксирован:
   `make_transcription` → `make_links` → `make_forms` → `make_blanks`.

3. **Вся лексика должна быть в словаре.** Каждое слово фразы и реплики диалога
   обязано иметь словарную статью: иначе ученик его не выучит. Проверяется
   тестом (`REQ-SENT-01`) и `tools/check_dialogues.py` (`REQ-DLG-05`).

4. **У каждой реплики диалога есть перевод.** Проверяется тестом (`REQ-DLG-01`).

5. **Правило артикля обязано воспроизводить все артикли словаря.**
   `make_forms.py --check` — самая полезная проверка данных: она уже ловила и
   ошибку в словаре (`il-omm` вместо `l-omm`), и дыру в самом правиле
   (`l-iskola`, `l-istudent`).

6. **Сборка — по явному списку файлов.** `bin/build` перечисляет файлы
   поимённо. Добавили файл данных в `index.html` — добавьте в `bin/build`,
   иначе он не попадёт на сайт. Ловится прогоном против `dist/`.

7. **Публикация проверяется по SHA коммита.** Статус `built` остаётся от
   предыдущей сборки, поэтому нужно сравнивать `pages/builds/latest.commit`
   с локальным `HEAD`, иначе тесты уйдут на старую версию сайта.

8. **Секретов в репозитории нет и быть не должно.** Приложение статическое,
   ключи API в него не попадают (см. историю: озвучку убрали именно поэтому).

## Как добавить материал

**Слово** — строка в `data/words.js`. Обязательны `mt` и `ru`. Для
существительных — `pos: "noun"`, `g` (род), `art` (артикль с ассимиляцией),
`pl` (множественное число). Для глаголов — `pos: "verb"`, `forms` и `pres`
(парадигма имперфетта: 3 л. ед. ч. м, 3 л. ед. ч. ж, 3 л. мн. ч).
Для прилагательных — `pos: "adj"` и `forms` (женская форма, при уверенности
и множественное число).

Потом: генераторы, затем `python3 tests/smoke.py` — проверка
`REQ-TR-01 every word and sentence has a transcription` укажет забытые слова.

**Фраза** — строка в `data/sentences.js` (`mt`, `ru`, `topic`). После
генераторов тест `REQ-SENT-01` покажет непривязанные слова — их нужно добавить
в словарь или в таблицу алиасов `tools/make_links.py`.

**Диалог** — объект в `data/dialogues.js`: `id`, `title`, `topic`, `note`,
`lines` (по 4–7 реплик, `who`: A/B, `mt`, `ru`). Проверить:
`python3 tools/check_dialogues.py`.

## Грабли, на которые уже наступали

- **`\n` в python-строке ломает JS-регулярку.** В тесте JS-выражение лучше
  собирать без `\n`, а нормализовать текст в Python.
- **Правки через heredoc молча не применяются**, если шаблон не совпал.
  После каждой замены проверяйте результат (`grep`), а не вывод скрипта.
- **`bin/build` содержит явный список файлов** — новый файл данных легко
  забыть (уже забывали `pairs.js` и `forms.js`).
- **localStorage привязан к адресу.** Прогресс с `maltese.localhost:8080` не
  виден на `dionique.github.io` — это разные хранилища, а не баг.
- **Гомографы.** Идентификатор слова — сама строка, поэтому два разных слова
  с одинаковым написанием (`qabel` — предлог и глагол) конфликтуют.
- **Омонимы при связывании.** `l-ġimgħa` — и пятница, и определённая форма
  слова «неделя»; такие случаи решаются таблицей алиасов, а не догадкой.
- **Тесты бывают флейкими от данных**: подписи и пороги лучше брать из данных
  (`window.DIALOGUES`, `window.WORDS`), а не хардкодить.

## Состояние

- Проверок: 208 (`tests/smoke.py`), прогоняются локально, против `dist/` и
  против живого сайта.
- Требований: 60 в `specs/`.
- Словарь: 431 слово, 395 фраз, 20 диалогов (123 реплики),
  392 упражнения на формы, 118 на пропуски.
- Мальтийский в данных писал агент; формы сверены с Викисловарём
  (`mess → jmiss` подтверждено) и с учебным заданием. Требуется проверка
  носителем — особенно парадигмы глаголов и диалоги.
