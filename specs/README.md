# Спецификации Il-Malti

Здесь лежат требования. Код и тесты пишутся **от требований**, а не наоборот.

## Рабочий цикл

1. **Требование.** Пишем или правим его в файле спецификации. У каждого —
   идентификатор вида `REQ-<ОБЛАСТЬ>-<НОМЕР>`. Формулировка должна быть
   проверяемой: не «удобно», а «кнопка появляется после ответа».
2. **Код.** Реализуем в `app.js` / `data/`.
3. **Тест.** Пишем проверку, в подписи которой есть идентификатор требования:
   ```python
   check("REQ-SENT-09 после ответа есть кнопка «Дальше»", ...)
   ```
   Именно по этой подписи работает трассировка, поэтому идентификатор в тесте
   обязателен.
4. **Прогон.** `python3 tools/check_specs.py` — проверяет, что нет требований
   без тестов и тестов без требований. Затем `bin/deploy` — тесты, сборка,
   публикация, проверка живого сайта.

## Правила

- **Требование без проверки — не требование.** `check_specs.py` упадёт.
- **Проверка без требования — тоже ошибка.** Либо требование забыли записать,
  либо проверка лишняя.
- Один идентификатор может использоваться в нескольких проверках.
- Меняем поведение — меняем формулировку требования в том же коммите.
- Проверяться может не только браузер: валидация данных живёт в инструментах
  (`tools/make_forms.py --check`, `tools/check_dialogues.py`), публикация —
  в `bin/deploy`. В них идентификатор указывается комментарием.
